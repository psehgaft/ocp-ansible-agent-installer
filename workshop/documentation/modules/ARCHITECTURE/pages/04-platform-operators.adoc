= Platform Operators

Module 4.4 installs and configures the platform services required after the OpenShift control plane is healthy. Operator installation and operand configuration are intentionally separate: OLM resources establish the operator lifecycle, while inventory-driven manifests create the platform service.

== Objectives

After completing this module, you can:

* Install operators from the declarative component catalog.
* Apply custom resources only after operator readiness.
* use `direct`, `render`, or `gitops` deployment modes.
* Keep channels, approval policy, storage credentials, registry credentials, and cloud credentials outside playbooks.
* Validate Subscription, InstallPlan, CSV, workload, custom-resource, and ClusterOperator health.
* Produce evidence and rollback data for every installed platform service.

== Shared execution model

All topic-specific playbooks call `playbooks/day2/platform-operator-bundle.yml`. Catalog-backed operators use `framework/components.yml`; services not yet represented in the catalog provide explicit Namespace, OperatorGroup, and Subscription resources.

[source,bash]
----
# Direct installation
ansible-playbook playbooks/day2/acm.yml \
  -e platform_deployment_mode=direct

# Render manifests for review
ansible-playbook playbooks/day2/platform-logging.yml \
  -e platform_deployment_mode=render

# Render into a GitOps working tree
ansible-playbook playbooks/day2/platform-networking.yml \
  -e platform_deployment_mode=gitops
----

Before production execution, verify the package, channel, CatalogSource, OpenShift compatibility, mirrored images, install-plan policy, capacity, default StorageClass, certificates, and backup strategy.

== Recommended installation order

. cert-manager and PKI prerequisites.
. Storage and networking foundations.
. Monitoring, logging, observability, and backup.
. ACM and ACS.
. Virtualization and MTV.
. AAP and Quay.
. Bare-metal, load-balancer, and RHOSO services.

== 4.4.1 ACM

Advanced Cluster Management provides hub-based lifecycle, governance, application placement, observability, and managed-cluster operations.

[source,bash]
----
ansible-playbook playbooks/day2/acm.yml \
  -e platform_deployment_mode=direct \
  -e @inventories/lab/group_vars/all/platform-operators.yml
----

Define `acm_resources` with the `MultiClusterHub`, optional `MultiClusterObservability`, policies, and placement resources. Validate:

[source,bash]
----
oc get subscription,csv -n open-cluster-management
oc get multiclusterhub -n open-cluster-management
oc get pods -n open-cluster-management
oc get managedcluster
----

== 4.4.2 ACS

Advanced Cluster Security provides image, deployment, runtime, compliance, vulnerability, and network-policy controls.

[source,bash]
----
ansible-playbook playbooks/day2/acs.yml
----

Define `acs_resources` with `Central` and `SecuredCluster` custom resources. Protect the central admin password, collector configuration, scanner database settings, and external integrations with Vault or an external secret manager.

== 4.4.3 Storage

The storage workflow installs ODF through the catalog and accepts additional resources for LVM Storage, Local Storage, CSI drivers, StorageSystems, StorageClusters, StorageClasses, and VolumeSnapshotClasses.

[source,bash]
----
ansible-playbook playbooks/day2/storage.yml \
  -e @inventories/lab/group_vars/all/storage.yml
----

Define `storage_operator_resources`. Validate node eligibility, device ownership, failure domains, capacity, reclaim policy, expansion, encryption, snapshots, and recovery before selecting a default StorageClass.

== 4.4.4 Virtualization

OpenShift Virtualization adds KubeVirt-based virtual-machine lifecycle to OpenShift.

[source,bash]
----
ansible-playbook playbooks/day2/virtualization.yml
----

Define `virtualization_resources` with the `HyperConverged` custom resource and optional namespace, templates, DataVolumes, and migration policies. Validate hardware virtualization, worker labels, storage profiles, live-migration networks, and `HyperConverged` conditions.

== 4.4.5 MTV

Migration Toolkit for Virtualization discovers source providers and migrates virtual machines into OpenShift Virtualization.

[source,bash]
----
ansible-playbook playbooks/day2/mtv.yml
----

Run this after Virtualization is healthy. Define `mtv_resources` with the ForkliftController, provider secrets, Providers, NetworkMaps, StorageMaps, and Plans. Store vCenter, RHV, or OpenStack credentials in encrypted variables.

== 4.4.6 AAP

Ansible Automation Platform provides controller, execution environments, automation mesh, event-driven automation, and centralized credentials.

[source,bash]
----
ansible-playbook playbooks/day2/aap.yml \
  -e aap_channel=stable-2.5 \
  -e aap_install_plan_approval=Manual
----

The playbook creates the AAP namespace, OperatorGroup, and Subscription by default. Override `aap_resources` to add `AnsibleAutomationPlatform`, `AutomationController`, `AutomationHub`, or `EDA` custom resources. Review the channel against the target catalog before use.

== 4.4.7 Cert Manager

cert-manager automates Issuer, ClusterIssuer, Certificate, renewal, and secret lifecycle.

[source,bash]
----
ansible-playbook playbooks/day2/platform-cert-manager.yml
ansible-playbook playbooks/day2/cert-manager.yml
----

The first playbook installs the operator; the second configures issuers and certificates. Keep CA private keys and external-provider credentials outside Git.

== 4.4.8 PKI

PKI configuration manages trust bundles, API and Ingress certificates, certificate policies, and integration with internal or external certificate authorities.

[source,bash]
----
ansible-playbook playbooks/day2/platform-pki.yml \
  -e @inventories/lab/group_vars/all/pki.yml
----

Define `pki_resources` with ConfigMaps, Secrets from protected inputs, Issuers, ClusterIssuers, Certificates, APIServer, IngressController, or Proxy trust resources. Validate SANs, chain order, key usage, rotation, and client trust before rollout.

== 4.4.9 Quay and Registries

Quay provides enterprise image storage, vulnerability scanning, mirroring, robot accounts, retention, and geo-replication.

[source,bash]
----
ansible-playbook playbooks/day2/platform-quay.yml
----

Define `quay_resources` with `QuayRegistry` and supporting storage, database, route, certificate, and configuration resources. Registry authentication, object-storage credentials, and database passwords must be encrypted.

== 4.4.10 Networking

The networking workflow installs NMState, SR-IOV, and MetalLB components and accepts Multus, NAD, NodeNetworkConfigurationPolicy, SriovNetworkNodePolicy, SriovNetwork, IPAddressPool, and advertisement resources.

[source,bash]
----
ansible-playbook playbooks/day2/platform-networking.yml \
  -e @inventories/lab/group_vars/all/networking.yml
----

Define `networking_operator_resources`. Apply NMState policies before workloads, validate SR-IOV firmware and IOMMU settings, reserve address pools, and avoid overlapping cluster, service, pod, machine, and load-balancer networks.

== 4.4.11 Monitoring

OpenShift monitoring is part of the cluster payload. This workflow manages configuration and monitoring operands rather than installing a separate operator.

[source,bash]
----
ansible-playbook playbooks/day2/platform-monitoring.yml \
  -e @inventories/lab/group_vars/all/monitoring.yml
----

Define `monitoring_resources` with cluster-monitoring-config, user-workload-monitoring-config, ServiceMonitor, PodMonitor, PrometheusRule, AlertmanagerConfig, and retention/storage settings.

== 4.4.12 Logging

Logging installs Loki first and then the Cluster Logging Operator. Operand resources define the LokiStack, ClusterLogForwarder, inputs, outputs, pipelines, retention, and tenancy.

[source,bash]
----
ansible-playbook playbooks/day2/platform-logging.yml \
  -e @inventories/lab/group_vars/all/logging.yml
----

Validate object storage, TLS, tenant mode, collector scheduling, forwarding destinations, flow control, and retention. Avoid embedding SIEM credentials in manifests.

== 4.4.13 Backup OADP

OADP provides Velero-based backup and restore for Kubernetes objects and supported persistent volumes.

[source,bash]
----
ansible-playbook playbooks/day2/platform-oadp.yml \
  -e oadp_channel=stable-1.5
ansible-playbook playbooks/day2/oadp.yml
----

The first playbook installs the operator; the second configures DPA and backup workflows. Override `oadp_resources` for disconnected catalogs or custom channels. Validate BackupStorageLocation, VolumeSnapshotLocation, DPA, test Backup, test Restore, and application consistency.

== 4.4.14 Cluster Observability Operator

The Cluster Observability Operator provides independent monitoring stacks and console integrations for application or platform teams.

[source,bash]
----
ansible-playbook playbooks/day2/platform-cluster-observability.yml
----

Define `cluster_observability_resources` with MonitoringStack, ThanosQuerier, UIPlugin, ServiceMonitor, PrometheusRule, and storage resources. Confirm that it complements rather than duplicates the built-in monitoring stack.

== 4.4.15 Network Observability Operator

Network Observability collects and analyzes network flows through eBPF agents, FlowCollector, optional Kafka, Loki, and console integration.

[source,bash]
----
ansible-playbook playbooks/day2/platform-network-observability.yml \
  -e netobserv_install_plan_approval=Manual
----

Override `network_observability_resources` to add an OperatorGroup, custom catalog configuration, and `FlowCollector`. Size flow sampling, Loki, Kafka, storage, and retention according to traffic volume.

== 4.4.16 Bare Metal Operator

The Bare Metal Operator is delivered with OpenShift and manages Provisioning and BareMetalHost resources.

[source,bash]
----
ansible-playbook playbooks/day2/platform-baremetal.yml
----

Define `baremetal_resources` with Provisioning configuration and BareMetalHost manifests. Validate BMC reachability, credentials, boot MACs, inspection, provisioning networks, and available state before automated provisioning.

== 4.4.17 Load Balancer Operator

The load-balancer workflow uses the MetalLB catalog component and configures MetalLB, IPAddressPool, BGPAdvertisement, L2Advertisement, BFDProfile, and BGP peer resources.

[source,bash]
----
ansible-playbook playbooks/day2/platform-load-balancer.yml \
  -e @inventories/lab/group_vars/all/load-balancer.yml
----

Define `load_balancer_resources`. Reserve non-overlapping addresses, confirm upstream routing or Layer-2 reachability, and test service failover.

== 4.4.18 RHOSO Operator

Red Hat OpenStack Services on OpenShift deploys OpenStack control-plane services on OpenShift and data-plane services on external nodes.

[source,bash]
----
ansible-playbook playbooks/day2/platform-rhoso.yml \
  -e @inventories/lab/group_vars/all/rhoso.yml
----

RHOSO depends on cert-manager and NMState. Define `rhoso_resources` with OpenStackControlPlane, OpenStackDataPlaneNodeSet, OpenStackDataPlaneDeployment, network definitions, secrets, and storage integrations. Validate operator CSVs, control-plane conditions, data-plane Ansible execution, network isolation, and service endpoints.

== Common validation

[source,bash]
----
oc get subscriptions.operators.coreos.com -A
oc get installplans.operators.coreos.com -A
oc get csv -A
oc get co
oc get pods -A --field-selector=status.phase!=Running,status.phase!=Succeeded
oc get events -A --sort-by=.lastTimestamp | tail -100
----

For Manual InstallPlans, review the CSV and related images before approval. Record namespace, Subscription, InstallPlan, CSV, workloads, custom-resource conditions, routes, storage usage, and rollback instructions in the workshop evidence package.
