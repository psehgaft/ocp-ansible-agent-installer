= Day-2 Activities with Playbooks

== Objective

Run explicit, validated Day-2 operational workflows after the cluster is
healthy. GitOps initialization is a separate procedure in
xref:21-gitops-playbook.adoc[1.4 GitOps Initialization].

== Select the activity

Use the implementation catalog to identify the canonical playbook and its
input file. Typical activity groups are:

|===
| Activity | Examples | Entry points

| Read-only validation
| Cluster health, etcd health, certificate audit, upgrade prechecks
| `health-checks.yml`, `etcd-health.yml`, `certificate-audit.yml`, `upgrade-prechecks.yml`

| Node foundation
| NTP, labels, machine configuration
| `ntp.yml`, `node-labels.yml`, `machineconfig.yml`

| Identity and trust
| OAuth, LDAP, HTPasswd, trusted CA, certificates
| `oauth.yml`, `ldap.yml`, `htpasswd.yml`, `trusted-ca.yml`, `install_certs.yml`

| Data protection and evidence
| etcd backup, OADP backup, must-gather, reports
| `etcd-backup.yml`, `backup-oadp.yml`, `must-gather.yml`, `reports.yml`
|===

Do not run a direct-change playbook against a resource already owned by Argo
CD. Change its Git desired state instead.

== Procedure

. Activate the exact cluster credentials and record the starting state.
+
[source,bash]
----
export KUBECONFIG=$PWD/artifacts/production-a/auth/kubeconfig
oc whoami
oc get clusterversion
oc get nodes -o wide
oc get clusteroperators
----

. Open the selected playbook and its role defaults. Configure every required
  variable in the environment inventory; keep secrets in Ansible Vault.

. Run syntax and inventory validation.
+
[source,bash]
----
ansible-inventory -i "$INVENTORY" --list >/dev/null
ansible-playbook -i "$INVENTORY" \
  --vault-password-file "$VAULT_PASSWORD_FILE" \
  playbooks/day2/health-checks.yml --syntax-check
----

. Begin with a read-only check or the playbook's documented `validate`/`render`
  mode. Example:
+
[source,bash]
----
ansible-playbook -i "$INVENTORY" \
  --vault-password-file "$VAULT_PASSWORD_FILE" \
  playbooks/day2/health-checks.yml
----

. Back up the affected resource before an approved mutation.
+
[source,bash]
----
mkdir -p evidence/production-a
oc get nodes -o yaml > evidence/production-a/nodes-before.yaml
oc get clusteroperators -o yaml > evidence/production-a/operators-before.yaml
----

. Run only the selected workflow. The following examples require their
  corresponding input files to be completed first.
+
[source,bash]
----
ansible-playbook -i "$INVENTORY" \
  --vault-password-file "$VAULT_PASSWORD_FILE" playbooks/day2/ntp.yml
ansible-playbook -i "$INVENTORY" \
  --vault-password-file "$VAULT_PASSWORD_FILE" playbooks/day2/node-labels.yml
----

. Verify the specific resource, ClusterOperator conditions, affected pods, and
  application smoke tests. Retain before/after evidence and the Ansible log.

== Success criteria

Only the approved component changed, its health checks pass, no GitOps-owned
resource drift was introduced, and evidence supports rollback.
