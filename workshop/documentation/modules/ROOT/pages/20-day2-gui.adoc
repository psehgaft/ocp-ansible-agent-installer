= Day-2 Activities with the GUI Interface

== Objective

Configure and preview Day-2 desired state through the GUI without pushing Git
content or changing the cluster. Publication and bootstrap are a separate
procedure in xref:22-gitops-gui.adoc[2.4 GitOps Initialization].

== Procedure

. Open the saved cluster profile and navigate to **Day-2 GitOps**.

. Confirm the cluster name and OpenShift minor version. Select a built-in
  profile or `custom`, then select only the operators required by the approved
  architecture. Dependencies are resolved automatically.

. Configure every applicable field: install-plan approval, channel adaptation,
  per-operator overrides, additional packages, catalog images, Git URL, branch,
  repository path, project, render root, checkout directory, and authentication
  mode.

. Add complete Kubernetes Custom Resources in the structured operands editor.
  Do not add `Secret` objects or inline credentials. Use an approved secret
  operator or encrypted bootstrap mechanism.

. Keep **Git push**, **Git push confirmed**, and **GitOps bootstrap** disabled.
  This makes the activity a local preview.

. Save the profile and run **Validate configuration**. Resolve every error.

. Select **Render Day-2 GitOps**. This action needs no impact confirmation
  because it does not write to Git or contact the cluster.

. Follow the redacted live log and download `render-summary.json` plus the
  rendered desired-state tree.

. Review Kustomize builds, operator dependencies, namespaces, channels, catalog
  sources, sync waves, operands, and the generated operator mirror
  configuration.

. For a disconnected cluster, complete the approved operator mirror process
  before attempting GitOps initialization.

== Success criteria

The desired state renders successfully, all values have been reviewed, Git and
the cluster remain unchanged, and the preview contains no plaintext secret.
