# Contributing to RHOSO Demo Lab Playground

Thank you for your interest in contributing to this project!

## How to Contribute

### Reporting Issues

- Use GitHub Issues to report bugs or request features
- Provide detailed information about the issue
- Include steps to reproduce if reporting a bug
- Mention your environment (OpenShift version, RHOSO version, etc.)

### Submitting Changes

1. Fork the repository
2. Create a feature branch from `main`
3. Make your changes
4. Test your changes thoroughly
5. Submit a pull request

### Pull Request Guidelines

- Provide a clear description of the changes
- Reference any related issues
- Ensure documentation is updated if needed
- Test automation scripts before submitting

### Code Style

- Shell scripts: Follow bash best practices, use `set -e` for error handling
- YAML: Use 2-space indentation, validate syntax
- Ansible: Follow Ansible best practices and style guide
- Documentation: Use clear, concise language

### Documentation

- Update relevant README files when adding features
- Add comments to complex automation scripts
- Include examples where helpful
- Keep documentation in sync with code

### Testing

When contributing automation:
- Test in a lab environment first
- Document any prerequisites
- Include error handling
- Provide rollback procedures where applicable

## Areas for Contribution

We welcome contributions in these areas:

- **Documentation**: Improve guides, add examples, fix typos
- **Automation**: Enhance scripts, add new playbooks
- **Examples**: Add configuration examples, manifests
- **Testing**: Add validation scripts, test procedures
- **CI/CD**: Improve automation pipelines

## Questions?

Feel free to open an issue for questions or discussions about contributing.

## Code of Conduct

- Be respectful and inclusive
- Focus on constructive feedback
- Help create a welcoming environment for all contributors
