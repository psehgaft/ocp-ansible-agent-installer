# Secret handling conventions

Secrets must never be committed as plaintext.

## Supported patterns

1. **Ansible Vault** for CLI and AAP inventories.
2. **External secret references** for GitOps deployments.
3. **Environment variables** for short-lived CI credentials.
4. **AAP credentials** when running through Ansible Automation Platform.

## Naming

Secret variables use the suffix `_secret`, `_password`, `_token`, or `_credential_ref` and must be marked `no_log: true` in tasks that consume them.

## Ansible Vault example

```bash
ansible-vault create inventories/production/group_vars/all/vault.yml
ansible-playbook playbooks/framework-runtime.yml \
  -i inventories/production/hosts.yml \
  --ask-vault-pass
```

Example encrypted variable names:

```yaml
vault_redfish_password: change-me-before-encryption
vault_ldap_bind_password: change-me-before-encryption
vault_registry_token: change-me-before-encryption
```

GitOps manifests must reference External Secrets, Sealed Secrets, SOPS-encrypted data, or another approved secret provider. Plain Kubernetes `Secret` values are not generated by default.
